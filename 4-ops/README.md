# Coder Nation Ops: النظام الداخلي للفريق

تطبيق داخلي (Next.js 16 + MySQL، عربي RTL) لفريق Coder Nation. **المراحل 1 و2 و3: الحسابات والأدوار + الـ CRM + العروض الفنية والمالية بـ PDF + المهام والمشاريع + الحضور والانصراف.**

> للفريق فقط، ومفيش SSO لسه (تسجيل دخول بإيميل وباسورد). لو هيتنشر على دومين، لازم الأول HTTPS وتقرير الـ SSO.

## التشغيل

```bash
npm install
mysql -uroot -e 'create database coder_nation_ops character set utf8mb4 collate utf8mb4_unicode_ci'
cp .env.example .env.local          # عدّل DATABASE_URL و IP_HASH_SALT و INTAKE_SECRET
npm run db:migrate
```

بعدين اعمل **المالك** بنفسك من Terminal عادي (بيسألك على الباسورد مخفي، ومينفعش من أداة بلا TTY):

```bash
npm run user:create -- --email you@example.com --name "اسمك" --role owner
npm run dev                         # http://localhost:3020
```

باقي الفريق بيتضافوا من `/settings/users` (المالك بس): بيتولّد لهم باسورد مؤقت بيظهر مرة واحدة، ولازم يغيّروه في أول دخول. نسيت باسورد؟ `npm run user:create -- --email ... --reset`.

الأوامر: `npm run build` · `npm start` · `npm test` · `npm run lint` · `npm run typecheck`.

## الـ CRM

مراحل الصفقة: **جديد ← تم التواصل ← اجتماع وتحديد المتطلبات ← عرض مُرسل ← تفاوض ← فاز / خسر** (الخسارة بسبب إجباري). كل تغيير وملاحظة ومكالمة بتتسجّل في سجل الصفقة، والمتابعات بتظهر في الرئيسية (والمتأخر بالأحمر). العميل بيتعرّف بالهاتف فمبيتكررش.

### ربط الموقع بالـ CRM

كل طلب جديد من فورم الموقع (`1-coder-nation`) بيتبعت هنا تلقائيًا كصفقة جديدة في «جديد»:

1. حط نفس السر في `INTAKE_SECRET` هنا (32+ حرف) وفي `OPS_INTAKE_SECRET` في `.env.local` بتاع الموقع، و`OPS_INTAKE_URL=http://127.0.0.1:3020/api/intake/website`.
2. الطلب موقّع (`X-Signature: sha256=HMAC(secret, "<timestamp>.<body>")` + `X-Timestamp`)، ومقبول لـ ±5 دقايق بس، وتكراره مبيعملش صفقة تانية (الـ id بتاع الـ lead فريد).
3. لو الـ CRM واقف، الـ lead بيفضل محفوظ في `/admin` بتاع الموقع، والزائر مبيحسش بحاجة (مهلة 2.5 ثانية). **مفيش إعادة محاولة تلقائية لسه.**

## العروض (فني + مالي) و PDF

من صفحة الصفقة: «عرض جديد لهذه الصفقة» بيعمل مسودة برقم `P-2026-0001` وقالب فني حسب نوع المشروع (موقع / تطبيق / متجر / UI-UX). القوالب **مسودات محايدة**: مفيهاش أسعار ولا مدد ضمان ولا ادعاءات، وكل `[...]` مكان لازم تملاه (المحرر بيعدّهم ويحذّرك).

- **المالي:** بنود (كمية × سعر)، خصم، ضريبة اختيارية بنسبة، عملة لكل عرض (EGP / USD / SAR / AED / EUR)، وجدول دفعات بنسب لازم يجمع 100%. كل الحسابات بأعداد صحيحة (قروش)، والإجماليات حيّة وهي نفسها اللي في الـ PDF.
- **PDF:** زرار «تصدير PDF» بيطبع صفحة `/proposals/:id/print` بـ Chrome headless (A4، العربي والخطوط مضبوطين، ترقيم صفحات، ورقم العرض في التذييل). بياخد ≈ 2 ثانية. لازم Chrome مثبّت (الافتراضي مسار macOS، أو `CHROME_PATH`).
- **التصدير متعطّل** لو مفيش بنود أو الدفعات مش 100% أو فيه تعديلات لسه ما اتحفظتش.
- «تم إرسال العرض للعميل» بيقفل العرض للتعديل (الأرقام اللي عند العميل لازم تفضل صح) وبينقل الصفقة لـ«عرض مُرسل» (لو كانت في مرحلة أبكر). للتعديل بعد الإرسال: «نسخة جديدة للتعديل» (رقم جديد).

## المهام والمشاريع

- **المهمة:** عنوان، وصف، مسؤول واحد، موعد تسليم، أولوية، وحالة: للعمل / جاري / مراجعة / تم، و«متعطّلة» لازم تتسجّل بسبب (والـ DB نفسها بترفض غير كده). كل نقل وإسناد وتعليق بيتسجّل في سجل المهمة. المهمة ممكن تكون مستقلة أو جوه مشروع، ومربوطة بصفقة أو عميل.
- **الموظف** بيشوف مهامه بس (مهمة زميله = «غير موجودة»)، بيحرّكها بين للعمل/جاري/مراجعة/متعطّلة ويعلّق، لكن **مبيقفلش «تم»** (ده دور المراجعة عند المدير) ومبيسندش ومبيعملش مشاريع. المشروع بيظهر له كحاوية لمهامه، وأعداد المهام جواه بتخص مهامه هو بس.
- **المتأخر:** موعد التسليم قبل النهارده بتوقيت القاهرة والحالة مش «تم»، ويظهر بالأحمر وفي الرئيسية (للمدير: عدّاد فريق كامل).
- **«ابدأ المشروع»** في صفحة صفقة «فاز» (مدير/مالك): بيعمل مشروع للعميل ومهمة لكل مرحلة في الجدول الزمني للعرض (المقبول، وإلا آخر مُرسل)، بمواعيد محسوبة من تاريخ البدء (تراكم الأسابيع، آخر يوم في الأسبوع). مشروع واحد لكل عرض (قيد فريد في الـ DB)، وضغطتين في نفس اللحظة بيعملوا واحد بس.
- التواريخ «أيام» مش لحظات: بتتعرض بنفس اليوم أيًّا كان توقيت السيرفر.
- مفيش إشعارات ولا مرفقات ولا مهام فرعية/متكررة ولا تتبّع وقت.

## الحضور والانصراف

- **الورديات:** لكل موظف وردية (بداية ونهاية وأيام شغل ومهلة تأخير، الافتراضي أحد-خميس 9-5 ومهلة 15 دقيقة) يحددها المدير من صفحة الشخص. **اللي معاهوش وردية مش متتبَّع** (مثلًا المالك) ومبيقدرش يسجّل. الغياب بيتحسب من يوم بدء التتبّع بس، فإضافة شخص متأخرًا مبتخترعش شهر غياب.
- **التسجيل:** زرار «سجّل الحضور» ثم «سجّل الانصراف» (في الرئيسية وفي `/attendance`)، **مرة واحدة في اليوم**. الوقت من ساعة السيرفر واليوم بتقويم القاهرة، مش من جهاز الموظف. التسجيل دايمًا باسم المستخدم الداخل، مش بـ id من الفورم.
- **التأخير:** لو الحضور بعد بداية الوردية بأكتر من المهلة، بيتسجّل عدد الدقايق من بداية الوردية (وبيتخزّن وقت التسجيل، فتغيير الوردية بعدين مبيغيّرش التاريخ). الحضور في يوم راحة **مش بيتحسب تأخير**.
- **الإجازات:** المدير يسجّلها لكل موظف (سنوية / مرضية / بدون مرتب / رسمية / أخرى)، مع خيار «لكل المتتبَّعين» للأعياد (بتتخزّن لكل شخص). مفيش تداخل: اللي عنده إجازة في الفترة بيتخطّى. أيام الإجازة مش بتتحسب غياب.
- **التصحيح:** الموظف مبيعدّلش. المدير بيضيف أو يعدّل أو يمسح تسجيل يوم **بسبب إجباري**، وكل تعديل بيتسجّل (مين، إمتى، القديم والجديد) ويفضل حتى لو اتمسح التسجيل. اليوم اللي فيه حضور من غير انصراف بيظهر للمدير.
- **التقارير:** «الفريق النهارده» (حاضر / متأخر / لم يسجّل / إجازة)، تقرير شهري لكل موظف (حضور، تأخير، غياب، إجازة، ساعات، أيام بدون انصراف)، وتصدير CSV للشهر (بيتعقّم ضد الـ formulas وبـ BOM لـ Excel). الموظف بيشوف ملخص شهره هو بس.
- **حدود:** الوردية لازم تخلص قبل منتصف الليل، والاستراحات مش بتتسجّل (حضور وانصراف مرة في اليوم)، ومفيش GPS أو تقييد بـ IP أو بصمة (تقدر تتضاف لاحقًا).

## الأمان

- كل صفحة وAction وroute بتنادي `requireUser()` / `requirePermission()` بنفسها. `src/proxy.ts` redirect سريع بس، مش الحماية الفعلية.
- باسورد scrypt بملح، جلسات DB (بيتخزّن hash التوكن)، كوكي `HttpOnly` + `SameSite=Strict` (+`Secure` في production). 5 محاولات دخول فاشلة / 15 دقيقة. حساب موقوف بيشوف نفس رسالة "الباسورد غلط"، وإيقافه بيقفل جلساته فورًا.
- الـ intake: HMAC + timestamp + حد حجم 10KB + rate limit، وكل الأخطاء بترجّع نفس الـ 401.
- الـ PDF بيفتح رابط التطبيق نفسه بس (`APP_URL`، مش من أي header)، وبجلسة المستخدم اللي طلبه.
- الفورمات `method="post"`: لو الـ JavaScript ما اتحمّلش، الباسورد عمره ما يروح في الـ URL.
- كل الـ SQL parameterized، وكل الـ headers صارمة (`no-store`, `frame-ancestors 'none'`, `noindex`). `IP_HASH_SALT` إجباري في production.

## حدود معروفة

- مفيش إرسال العرض بالإيميل، ولا توقيع إلكتروني، ولا فواتير ومدفوعات.
- العملات الخمس بخانتين عشريتين، ومفيش تحويل بينها.
- الـ PDF محتاج Chrome على نفس الجهاز، فالنشر على serverless هيحتاج `@sparticuz/chromium`.
- أول دخول للمالك بيتعمل من الـ terminal بس (مفيش تسجيل ذاتي).
